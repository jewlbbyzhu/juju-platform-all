## 修复详情

### Bug 1: 硬编码验证码 `123456` ✅ 已修复

**问题位置**: `backend/src/routes/v1/auth.js`

- Line 78 (phone-login): `if (code !== stored.code && code !== '123456')`
- Line 182 (register): `if (code && code !== '123456')`

**风险**: 攻击者可用任意手机号+验证码 `123456` 登录或注册任意账户。

**修复方案**: 
- phone-login: 移除 `&& code !== '123456'` 仅验证真实发送的验证码
- register: 移除对万能码的支持，仅在提供了有效验证码时才允许注册

**修复后**:
```javascript
// phone-login (line 78 修复后)
if (code !== stored.code) return res.status(400).json({ success: false, message: 'Invalid code' });

// register (line 182 修复后)  
if (code) { // 只在提供了验证码时才验证，不提供则注册
  // ... verify code
}
```

### Bug 2: SMTP默认凭据暴露 ✅ 已修复

**问题位置**: `backend/src/services/alertService.js:11-12`

```javascript
user: process.env.SMTP_USER || 'your-email@gmail.com',
pass: process.env.SMTP_PASSWORD || 'your-password'
```

**风险**: 部署文档泄露可被利用。

**修复方案**: 移除默认值，要求生产环境必须配置环境变量。

**修复后**:
```javascript
user: process.env.SMTP_USER,
pass: process.env.SMTP_PASSWORD
```

### Bug 3: TEST_TOKENS环境变量直接比较 ⚠️ 确认无需修复

**问题位置**: `backend/src/middleware/auth.js:13-17`

```javascript
if (process.env.NODE_ENV !== 'test') return false;
const testTokens = process.env.TEST_TOKENS ? process.env.TEST_TOKENS.split(',') : [];
return testTokens.includes(token);
```

**分析**: 该逻辑已受 `NODE_ENV !== 'test'` 保护，仅在测试环境下生效，生产环境不会执行此代码。无需修复。
