## 关键发现

### 1. 导航Bug未修复（回归）
- **项目上下文标记**: "✅ 已修复（2026-05-01 15:04）"
- **实际状态**: ❌ **未修复**
- **根因分析**: `App.tsx:154-178` 的 `BackHandler` 只拦截 `currentRoute?.name !== 'Main'` 的情况，对Login页返回 `false`（让系统处理退出）。Login Screen也未设置 `gestureEnabled: false` 或拦截返回键。
- **影响**: 用户启动APP后如果不想登录，按BACK键会直接退出APP（这是预期行为吗？需要产品确认）
- **注意**: 如果是**产品设计**（强制登录，不允许跳过），则需要在登录页拦截BACK键并提示"必须登录才能使用"。当前行为是静默退出，用户体验差。

### 2. ADB与RN TextInput兼容性限制
- `adb shell input text 13800138000` 只能输入前6位
- 逐个 `keyevent` 输入也只能输入6位
- **原因**: React Native TextInput的文本变更事件处理与ADB输入机制存在兼容性问题
- ** workaround**: 使用Appium的 `send_keys` 或直接在JS层mock输入

### 3. 微信登录功能未实现
- 点击微信登录图标显示"微信登录功能开发中"
- 这是已知状态，非Bug

### 4. 前端校验正常工作
- 空手机号点击"获取验证码" → 提示"请输入正确的手机号"
- 不完整手机号（138）点击 → 同样提示
- 弹窗UI正常，OK按钮可点击关闭

## 建议

1. **修复BACK键导航**: 在 `LoginScreen.tsx` 添加 `useFocusEffect` + `BackHandler` 拦截，或设置 `gestureEnabled: false`
2. **使用Appium进行完整登录测试**: 绕过ADB输入限制，使用WebDriver协议直接操作元素
3. **确认产品设计**: 登录页BACK键行为是"退出APP"还是"提示必须登录"？
